# 当前开发进度（2026-09-30 01:00 · 版本 1.0.1）

本轮为安全修复轮：按“全项目分析 → 全部修复”的结论，修掉状态接口越权、红娘登录链路断裂、明文身份证残留三个问题。

## 已完成

1. **状态序列化改为按角色最小化输出**
   - 新增 `server/state-visibility.js`，导出 `serializePublicState()`，要求显式传入角色和账号，非 admin 缺角色直接抛错，不再默认落到管理员全量视图。
   - `users` 对客户按白名单字段输出，不返回手机号、邮箱、真实姓名、微信、`profileByMatchmaker`；对红娘只保留自己的业务资料，并去掉手机号、邮箱、真实姓名。
   - `requests`、`chatThreads`、`chatMessages` 按参与者过滤：`member_matchmaker` 一对一私聊只看得到自己参与的线程，不再靠 `requestId` 把同一牵线下的另一方私聊带出来。
   - 红娘视角不再包含成交数据和平台分成配置；客户视角只保留自己的成交和已使用兑换码。
   - `GET /api/state` 角色收紧为 `admin` + `matchmaker`，客户不再有整包读权限（`PUT /api/state` 本来就是 admin 专属）。

2. **注册接口不再泄漏全量快照**
   - `/api/auth/client/register`、`/api/auth/matchmaker/register` 的响应只返回 `token` 和本人脱敏后的资料，删掉原来的 `state: publicState(state)`（该调用没传角色，等于匿名用户拿到管理员快照）。

3. **补充公开的最小化接口**
   - 新增 `GET /api/public/agencies`：未登录也能读到机构名称和城市，仅够红娘注册表单使用。
   - 红娘登录页不再依赖受保护的 `/api/state` 提前拉列表，改为账号 + 密码登录，登录成功后再按角色取数据。

4. **登录链路前后端对齐**
   - 红娘工作台登录改为“手机号 / 邮箱 / 红娘识别码 + 密码”，服务端按账号字段匹配（识别码比较时忽略大小写）。
   - 客户与红娘的“按 ID 一键登录”被服务端拒绝：缺少 `account` 返回 `400 account_required`，`userId` / `matchmakerId` 参数不再被解析。
   - 红娘注册的“推荐码”改名为“设置红娘唯一识别码”，格式收敛为 3-32 位字母、数字、下划线或连字符；按用户注释，开发阶段不加短信/手机号验证，保留原有手机号格式校验。
   - 遗留静态页 `matchmaker.html`、`index.html` 增加登录密码输入框，`app.js` 的登录/注册改为账号密码并用 `syncStateFromServer()` 重新拉取状态，不再依赖注册响应里的旧快照。

5. **实名认证改为模拟语义，明文身份证不再入库**
   - 提交实名时只用身份证号算年龄，`delete user.idCard`，只保留 `idCardMasked`（前 6 后 4），并写入 `realNameVerificationMode: "simulation"`。
   - 学历认证写入 `verificationMode: "simulation"`，视频认证写入 `videoVerificationMode: "simulation"`，`/api/client/verify-status` 返回对应的认证模式字段。
   - 客户端实名页文案明确标注“开发测试模拟，未连接公安身份核验，请勿提交真实身份证信息”。
   - 新增一次性迁移 `20260929_remove_plaintext_id_cards`：建 `app_migrations` 表，用 JSONB 谓词只挑真正写入号码的行，递归删除 `idCard`，重复启动不重复执行。

6. **测试与部署加固**
   - 新增回归测试 `scripts/test-state-visibility.mjs`（按客户/红娘/管理员三个视角断言字段与会话隔离）和 `scripts/test-auth-contracts.mjs`（注册不返回快照、拒绝 ID 登录、公开机构接口、迁移与备份、Dockerfile 内容），并入 `npm test`。
   - 修正线上全业务审计脚本：红娘按 `HM-LILI` + 密码登录，客户牵线响应断言“只看得到自己的一对一线程”，管理员快照断言三条线程都在，并新增“客户不能读整包状态”用例。
   - `server/Dockerfile` 改为复制 `package-lock.json`、用 `npm ci --omit=dev`，并复制 `state-visibility.js`（此前镜像会缺失新模块导致 API 起不来）。
   - `deploy/auto-deploy.sh` 在检测到 `server/` 变更、重建 API 前自动 `pg_dump` 到 `/opt/matchmaker/backup/postgres`，备份失败立即中止部署。
