# 状态接口越权与红娘登录链路修复（2026-09-30 01:00）

## 问题现象

全项目梳理时发现链式问题：

1. **匿名注册即拿到全站快照**：`publicState()` 的默认角色是 `admin`，而 `/api/auth/client/register` 和 `/api/auth/matchmaker/register` 都写成 `publicState(state)`，没有传角色。匿名用户注册成功后，响应里会带上全量用户、红娘、机构、牵线请求和全部聊天消息。
2. **整包状态接口权限过宽**：`GET /api/state` 允许 `client` 角色访问，非管理员分支只过滤了 `chatThreads` / `chatMessages` / `deals` / `promoCodes`，`requests` 未按角色收窄，其他用户资料也只删了 `phone` / `email` / `realName`，微信号和 `profileByMatchmaker` 仍在。
3. **红娘登录页根本登不进去**：登录页进入时调用 `appStore.fetchState()` 拉红娘列表，但该接口需要令牌；即使拿到列表，页面只提交 `matchmakerId`，服务端却要求密码。
4. **明文身份证号长期落库**：`/api/client/real-name` 把完整身份证号写进 `users.raw`，同时声称“任何接口都不返回完整身份证号”。

## 根因

- 序列化函数用“默认参数”表达权限，调用方漏传角色时静默升级为管理员视图。
- 安全边界按“字段名”思考（删掉某个字段）而不是按“调用者能看到什么范围”思考。
- 前端登录前置数据依赖了本该鉴权的接口，登录契约前后端不一致。
- 敏感数据“入库存明文、出接口靠脱敏”，一旦某个接口漏删就是泄露。

## 处理方式

- 新增 `server/state-visibility.js`，把“按角色输出”变成显式签名：`serializePublicState(data, viewerRole, viewerId, ensureMatchmakerMetrics)`，非 admin 必须传 `viewerId`，角色不在白名单直接抛错。
- 会员资料改为白名单字段输出，红娘视角只保留自己服务的会员且去掉联系方式。
- 会话过滤从“`requestId` 相关”改成“当前角色必须出现在 participants 里”。
- 注册响应删掉 `state`；新增 `GET /api/public/agencies` 给注册表单提供最小数据。
- 登录统一为账号（手机号/邮箱/微信号或红娘识别码）+ 密码，服务端拒绝按 ID 登录。
- 实名只用号码算年龄，落库只保存掩码；新增一次性迁移清理历史明文字段，并在 `app_migrations` 记账。

## 经验

- 凡是“带视图参数并带默认值”的函数，都要逐个核对调用点；默认值会成为最宽松的那条路径。
- 判断信息泄露不能只看“显式删了哪些字段”，要看某个角色最终能拼出什么。
- 前端如果需要一个公开列表，就显式提供最小化的公开接口，不要复用需要鉴权的数据接口。
- 改这类链路时，用真实数据库跑一遍“注册 → 登录 → 取状态 → 断言字段”比单元测试更能发现问题（本次就是靠本地冒烟发现红娘侧仍带出 `phone` / `email`）。
