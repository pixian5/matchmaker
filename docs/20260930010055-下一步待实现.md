# 下一步待实现（2026-09-30 01:00 · 版本 1.0.1）

## P0：上线前置

1. **旧演示账号清查**：生产库里的种子账号仍然使用 `123456` 默认密码，README 也公开了这些账号。需要确认线上库是否还有这类账号，评估停用、改密或删号，并保留操作记录。
2. **真实身份/学历/视频核验**：目前三类认证都是模拟流程，只做格式和出生日期校验。接入真实核验服务前，不能对外宣称“已实名”。

## P1：安全与权限

3. **管理员账号体系**：目前只有一个管理员，密码来自 `.env` 的 `ADMIN_PASSWORD`，明文比较且无操作日志。后续改为 `admins` 表 + 哈希存储 + 多管理员 + 审计日志。
4. **红娘注册是否需要审批**：现在是自助注册并直接签发红娘令牌。若产品要求邀请制或机构审批，需要加审批状态；若保持自助，需要在文档里明确这是预期边界。
5. **聊天历史分页**：`GET /api/client/chat/threads/:id/messages` 仍是全量返回，消息量上涨后会拖慢接口，需要加分页或游标。
6. **敏感词与传输安全**：敏感词库和遮挡规则仍在前端文档描述中存在，实际规则集中在 `server/index.js`；Token 仍是自研 HMAC，存储在前端本地存储，后续评估标准 JWT 与 httpOnly Cookie。

## P2：架构与质量

7. **拆分 `server/index.js`**：当前单文件约 3700 行，路由、状态序列化、数据库、WebSocket 混在一起。建议按 `state-visibility.js` 的模式继续拆 `routes/`、`db/`、`realtime/`。
8. **替换整包状态读写**：`PUT /api/state` 与 `syncNormalizedState()` 仍是全表 UPSERT + 删除不在列表中的行，并发下有覆盖风险。按角色拆细接口，最终下线整包读写。
9. **遗留静态端下线**：`app.js` 约 4600 行、`index.html` / `matchmaker.html` / `admin.html` 与 uniapp 功能重复，维护成本高。建议先确认静态页是否还有访问方，再决定保留或删除。
10. **更完整的自动化测试**：现有回归测试以源码契约和序列化断言为主。建议补 API 行为测试（登录拒绝、权限矩阵、牵线状态机、聊天隔离），以及一个可本地跑的集成用例，替代依赖线上写数据的 `scripts/full-business-audit.mjs`。
11. **数据库迁移体系**：目前迁移逻辑写在服务启动代码里，只能追加“一次性修补”。后续改为带版本号的迁移脚本目录，配合 `app_migrations` 表执行。
